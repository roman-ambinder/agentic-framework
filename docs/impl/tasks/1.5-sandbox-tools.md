# 1.5 — shell, git, search and file tools in the sandbox

Size: M · Depends on: 0.7.2, 1.4.2 · Branch: `task/1.5-sandbox-tools` · PR title: `1.5: sandbox-backed shell, git, search and file tools`

## Goal

After this task the agent can work inside a sandbox through four MCP servers:

| Tool (namespaced) | Does | Risk class |
|-------------------|------|-----------|
| `shell__run` | runs a shell command in `/workspace` | `EXEC` |
| `git__status` | `git status` of the workspace | `READ` |
| `git__diff` | `git diff` of the workspace | `READ` |
| `search__grep` | searches file contents | `READ` |
| `files__read_file` | reads a file | `READ` |
| `files__write_file` | creates or replaces a file | `WRITE_LOCAL` |
| `files__list_dir` | lists a directory | `READ` |

The servers are commands of the `adlc` binary (`adlc tool shell --sandbox ID`
etc.) and run **on the host**. They do the work by calling `Sandbox.Exec` on
an existing sandbox. These tool names are fixed; the coder agent (task 1.10)
uses them.

## Design

### Why the servers run on the host

The sandbox image only needs a shell, `git` and the project's toolchain. It
does not need the `adlc` binary, and nothing has to be copied into it. The
server process only needs the sandbox handle (the container id) to call
`Exec`. A Docker handle is just the container id, so a separate process can
use it.

### Shared helpers (`internal/tools/sandboxtool`)

```go
package sandboxtool

type Options struct {
	Sandbox        sandbox.Sandbox
	Handle         sandbox.Handle
	DefaultTimeout time.Duration // 0 = 2 * time.Minute
	MaxTimeout     time.Duration // 0 = 10 * time.Minute
}

// ExecMeta is the structured part of every exec-based tool result.
type ExecMeta struct {
	ExitCode int  `json:"exit_code"`
	TimedOut bool `json:"timed_out"`
}

// Run executes cmd in the sandbox with timeout (0 = DefaultTimeout).
// It returns an error only if the command could not be run at all.
func (o Options) Run(ctx context.Context, cmd []string, timeout time.Duration) (sandbox.ExecResult, error)

// Format renders a result for the model:
//
//	exit_code: 1
//	timed_out: true            <- only when TimedOut
//	--- stdout ---
//	...
//	--- stderr ---
//	...
//
// A section whose content is empty is written as "(empty)".
func Format(r sandbox.ExecResult) string

// TextResult builds an MCP result with one TextContent.
func TextResult(text string, isError bool) *mcp.CallToolResult

// CheckPath returns an error unless p is "." or a relative path that stays
// inside the workspace (filepath.IsLocal). Error text:
//	path %q must be relative to the workspace and must not contain ".."
func CheckPath(p string) error
```

`Format` never truncates: the sandbox already caps output at 8 MiB and the
tool router caps what the model sees (`interfaces.md §5`).

Every server is built with `mcp.NewServer(&mcp.Implementation{Name: "adlc-<name>", Version: buildinfo.Get().Version}, nil)`
and tools are added with `mcp.AddTool(server, &mcp.Tool{Name: ..., Description: ...}, handler)`.
The input schema is inferred from the `In` struct; descriptions come from the
`jsonschema:"..."` tag. Handlers return `(*mcp.CallToolResult, sandboxtool.ExecMeta, error)`
for exec-based tools; returning a non-nil `error` makes the SDK send a tool
error, which is how "could not run" is reported.

### `internal/tools/shell`

```go
func NewServer(o sandboxtool.Options) *mcp.Server

type RunInput struct {
	Command        string `json:"command" jsonschema:"shell command; runs with sh -c in /workspace"`
	TimeoutSeconds int    `json:"timeout_seconds,omitempty" jsonschema:"timeout in seconds, default 120, max 600"`
}
```

Tool `run`, description: `Run a shell command in the project workspace (/workspace) and return its exit code, stdout and stderr.`

Handler:

1. `Command` empty (after `strings.TrimSpace`) → error `command is empty`.
2. `TimeoutSeconds < 0` or `> int(MaxTimeout.Seconds())` → error
   `timeout_seconds must be between 1 and 600` (use the actual max).
3. `res, err := o.Run(ctx, []string{"sh", "-c", in.Command}, time.Duration(in.TimeoutSeconds)*time.Second)`; `err` → return it.
4. Return `TextResult(Format(res), res.ExitCode != 0 || res.TimedOut)`,
   `ExecMeta{res.ExitCode, res.TimedOut}`, nil.

### `internal/tools/git`

```go
func NewServer(o sandboxtool.Options) *mcp.Server
type StatusInput struct{}
type DiffInput struct {
	Path   string `json:"path,omitempty" jsonschema:"limit the diff to this file or directory"`
	Staged bool   `json:"staged,omitempty" jsonschema:"show staged changes instead of unstaged ones"`
}
```

- `status`: runs `["git", "status", "--porcelain=v1", "--branch", "--untracked-files=all"]`.
  Description: `Show changed, staged and untracked files in the workspace (git status).`
- `diff`: `CheckPath(in.Path)` if non-empty; runs
  `["git", "--no-pager", "diff", "--no-color", "--no-ext-diff"]` + `["--staged"]` if
  Staged + `["--", in.Path]` if Path is set. Description:
  `Show line changes in tracked files (git diff). New untracked files are listed by git__status, not here.`
- Both: `IsError` = `ExitCode != 0`. A workspace that is not a git repo gives
  git's own error text in stderr; do not special-case it.

### `internal/tools/search`

```go
func NewServer(o sandboxtool.Options) *mcp.Server
type GrepInput struct {
	Pattern    string `json:"pattern" jsonschema:"regular expression (extended syntax)"`
	Path       string `json:"path,omitempty" jsonschema:"file or directory to search, default ."`
	IgnoreCase bool   `json:"ignore_case,omitempty"`
	MaxResults int    `json:"max_results,omitempty" jsonschema:"maximum matching lines to return, default 200, max 1000"`
}
```

Tool `grep`, description: `Search file contents in the workspace for a regular expression. Returns path:line:text lines.`

Handler:

1. `Pattern` empty → error `pattern is empty`. `Path` empty → `"."`; `CheckPath(Path)`.
2. `MaxResults` 0 → 200; `< 0` or `> 1000` → error `max_results must be between 1 and 1000`.
3. Decide the program **once per server** (cache with `sync.Once`): run
   `["sh", "-c", "command -v rg"]`; exit code 0 → ripgrep, otherwise grep.
4. Command:
   - ripgrep: `["rg", "--line-number", "--no-heading", "--color", "never", "--hidden", "--glob", "!.git"]` + `["-i"]` if IgnoreCase + `["-e", Pattern, "--", Path]`
   - grep: `["grep", "-rnIE", "--exclude-dir=.git"]` + `["-i"]` if IgnoreCase + `["-e", Pattern, "--", Path]`
5. Exit code 1 with empty stderr → result text `no matches`, `IsError` false.
   Exit code ≥ 2, or 1 with stderr → `Format(res)`, `IsError` true.
6. Exit code 0 → split stdout into lines; keep the first `MaxResults`; if
   more, append `[%d more matching lines not shown]`. `IsError` false.

The pattern is passed as an argument, never through a shell.

### `internal/tools/files`

```go
func NewServer(o sandboxtool.Options) *mcp.Server

// MaxWriteBytes caps write_file content.
const MaxWriteBytes = 1 << 20 // 1 MiB

type ReadInput  struct{ Path string `json:"path" jsonschema:"file path relative to /workspace"` }
type WriteInput struct {
	Path    string `json:"path" jsonschema:"file path relative to /workspace"`
	Content string `json:"content" jsonschema:"the complete new file content"`
}
type ListInput struct{ Path string `json:"path,omitempty" jsonschema:"directory relative to /workspace, default ."` }
```

| Tool | Description | Command |
|------|-------------|---------|
| `read_file` | `Read a text file from the workspace.` | `["cat", "--", Path]` |
| `list_dir` | `List the entries of a directory in the workspace. Directories end with /.` | `["ls", "-1Ap", "--", Path]` |
| `write_file` | `Create or replace a file in the workspace with the given content. Parent directories are created.` | see below |

`read_file` and `list_dir`: success → stdout as the text (no `Format`
wrapper); non-zero exit → `Format(res)`, `IsError` true.

`write_file` (the sandbox has no stdin, so content is sent as base64 in
command arguments, in chunks below the kernel's per-argument limit):

1. `CheckPath(Path)`; `Path == "."` → error `path must name a file`.
2. `len(Content) > MaxWriteBytes` → error `content is larger than 1048576 bytes`.
3. Create the parent directories and an empty file (command 1 below).
4. `enc := base64.StdEncoding.EncodeToString([]byte(Content))`; for each
   chunk of `enc` of at most 65536 characters (chunk boundaries at multiples
   of 4, which 65536 is), append it (command 2 below).
5. Any non-zero exit → `Format(res)`, `IsError` true, stop.

```go
// command 1: Path is passed as $1, never inside the script text
[]string{"sh", "-c", `mkdir -p -- "$(dirname -- "$1")" && : > "$1"`, "sh", in.Path}

// command 2: chunk is $1, Path is $2
[]string{"sh", "-c", `printf '%s' "$1" | base64 -d >> "$2"`, "sh", chunk, in.Path}
```
6. Success text: `wrote %d bytes to %s`.

### `internal/tools/sandboxset` — the router other tasks use

The eval runner (task 1.8) needs a `toolrouter.Router` for a sandbox without
starting subprocesses. `sandboxset` serves the four servers in the same
process over in-memory transports and connects them with the MCP router from
task 0.7.2.

```go
package sandboxset

// ServerConfigs returns the four servers' configs with their risk classes,
// as in the Goal table. Command is the subprocess form
// ["adlc", "tool", <name>, "--sandbox", sandboxID]; NewRouter does not run it.
func ServerConfigs(sandboxID string) []mcprouter.ServerConfig

// NewRouter serves shell, git, search and files for o.Sandbox/o.Handle in
// this process and returns a router over them. Close the router when done.
func NewRouter(ctx context.Context, o sandboxtool.Options) (*mcprouter.Router, error)
```

`ServerConfigs` sets, per server: `Name` (`shell`, `git`, `search`, `files`),
`Command` as above, and the risks:

| Server | `Risk` | `DefaultRisk` |
|--------|--------|---------------|
| shell | `{"run": RISK_CLASS_EXEC}` | `UNSPECIFIED` |
| git | — | `RISK_CLASS_READ` |
| search | — | `RISK_CLASS_READ` |
| files | `{"write_file": RISK_CLASS_WRITE_LOCAL}` | `RISK_CLASS_READ` |

`NewRouter` steps:

1. `cfgs := ServerConfigs(o.Handle.ID)`; servers in the same order:
   `shell.NewServer(o)`, `git.NewServer(o)`, `search.NewServer(o)`, `files.NewServer(o)`.
2. For each: `ct, st := mcp.NewInMemoryTransports()`;
   `if _, err := server.Connect(ctx, st, nil); err != nil { return nil, fmt.Errorf("sandboxset: serve %s: %w", name, err) }`;
   collect `mcprouter.Conn{Config: cfg, Transport: ct}`.
3. `return mcprouter.Connect(ctx, conns)`. Closing the router closes the
   client sessions, which ends the in-memory server sessions.

The subprocess path (`adlc tool <name> --sandbox ID`, below) is for agent
configs that list the servers themselves; both paths give identical tools.

## Out of scope

- Committing, branching or pushing with git (the eval runner takes the diff).
- Editing parts of a file (search/replace); `write_file` replaces whole files.
- Running these servers inside the sandbox.
- The host-side `fs` tools from task 0.8 are **not** used for sandboxed
  runs: they see the host copy, not the sandbox copy.
- Other sandbox backends for the CLI (`--backend` accepts only `docker`).

## Pitfalls

- Commands in the `Host` test sandbox run in a temp dir, not `/workspace`:
  every command must use relative paths.
- Never build a shell string from model input. Model input is passed as
  separate argv items (`sh -c '...' sh "$1"`), which the shell does not interpret.
- Base64 chunks must be split at multiples of 4 characters, otherwise
  `base64 -d` fails on the chunk boundary.
- `grep`/`rg` exit code 1 means "no matches", not failure.
- A non-zero exit code is a tool error (`IsError`), not a Go error. Return a
  Go `error` only when the command could not run.
- Writing anything to stdout in the CLI commands corrupts the MCP stream.
