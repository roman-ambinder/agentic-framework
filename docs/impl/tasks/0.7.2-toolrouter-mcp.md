# 0.7.2 — MCP tool router

Size: M · Depends on: 0.7.1 · Branch: `task/0.7.2-toolrouter-mcp` · PR title: `0.7.2: MCP tool router`

## Goal

Package `internal/toolrouter/mcprouter` provides a `toolrouter.Router` that
starts MCP servers as subprocesses (stdio), lists their tools, namespaces them
as `<server>__<tool>`, attaches a risk class to each from config, and runs
calls. Tests run against in-process MCP servers over in-memory transports, so
they need no subprocess.

Behaviour verified with v1.8.0 (rely on it):
- `Tool.InputSchema` on the client side is a `map[string]any`; `json.Marshal` gives the JSON Schema.
- `CallToolParams.Arguments` can be a `json.RawMessage`; it is sent unchanged.
- When a server handler returns an error, the client gets `IsError: true` and one `*TextContent` with the error text (no Go error).
- Arguments that fail the tool's input schema give `IsError: true` with a "validating ..." text.
- Calling an unknown tool name returns a Go error from `CallTool`.

## Design

```go
package mcprouter

// ServerConfig describes one MCP server.
type ServerConfig struct {
	Name        string                      // namespace, e.g. "fs"
	Command     []string                    // argv; Command[0] is the program
	Env         map[string]string           // added to the parent's environment
	Dir         string                      // working directory; "" = parent's
	Risk        map[string]adlcv1.RiskClass // tool name (not namespaced) -> risk
	DefaultRisk adlcv1.RiskClass            // for tools not in Risk; UNSPECIFIED = none
}

// Validate checks the config itself (not the tools). Exact errors:
//   "mcprouter: server name %q must match ^[a-z][a-z0-9_]{0,15}$ and not contain \"__\""
//   "mcprouter: server %q has no command"
func (c ServerConfig) Validate() error

// Conn is a server plus an already-built transport (used by tests and by Start).
type Conn struct {
	Config    ServerConfig
	Transport mcp.Transport
}

// Router implements toolrouter.Router over MCP sessions.
type Router struct {
	tools    []toolrouter.Tool
	byName   map[string]entry // namespaced name -> entry
	sessions []*mcp.ClientSession
	now      func() time.Time
}

type entry struct {
	session *mcp.ClientSession
	tool    string // original (not namespaced) name
}

// Start launches every server as a subprocess and connects to it.
func Start(ctx context.Context, servers []ServerConfig) (*Router, error)

// Connect connects over the given transports. Start calls it.
func Connect(ctx context.Context, conns []Conn) (*Router, error)

func (r *Router) Tools() []toolrouter.Tool
func (r *Router) Call(ctx context.Context, call model.ToolCall) (toolrouter.Result, error)
func (r *Router) Close() error

var _ toolrouter.Router = (*Router)(nil)
```

Client identity: `mcp.NewClient(&mcp.Implementation{Name: "adlc", Version: buildinfo.Get().Version}, nil)`.

### `Start`

1. For each config: `Validate()`; return the first error.
2. Build `cmd := exec.Command(c.Command[0], c.Command[1:]...)`. Do **not** use
   `exec.CommandContext`: the router outlives the `ctx` passed to `Start`,
   and `CommandContext` would kill the server when that ctx ends.
3. `cmd.Dir = c.Dir`; `cmd.Env = append(os.Environ(), "K=V"...)` for each `Env`
   entry, sorted by key (deterministic). `cmd.Stderr = os.Stderr` (servers
   log there; stdout is the protocol).
4. `conns = append(conns, Conn{Config: c, Transport: &mcp.CommandTransport{Command: cmd}})`.
5. `return Connect(ctx, conns)`.

### `Connect`

`Connect` does not call `ServerConfig.Validate` and never runs `Command`: the
transport is already built. (Task 1.5 passes in-memory transports with a
`Command` that is only informational.) It only uses `Name`, `Risk` and
`DefaultRisk` from the config.

1. Reject duplicate server names: `mcprouter: duplicate server %q`.
2. For each conn, in order:
   1. `session, err := client.Connect(ctx, conn.Transport, nil)`; on error close
      all sessions opened so far and return
      `fmt.Errorf("mcprouter: connect %s: %w", name, err)`.
   2. List tools with `for t, err := range session.Tools(ctx, nil)`. On error:
      close all, return `mcprouter: list tools of %s: %w`.
   3. For each tool, build:
      ```go
      schema, err := json.Marshal(t.InputSchema)            // error -> close all, return
      risk := conn.Config.Risk[t.Name]; if risk == UNSPECIFIED { risk = conn.Config.DefaultRisk }
      tool := toolrouter.Tool{
          Spec:   model.ToolSpec{Name: toolrouter.Namespaced(name, t.Name), Description: t.Description, InputSchema: schema},
          Server: name,
          Risk:   risk,
      }
      ```
      If `risk` is still UNSPECIFIED: error
      `mcprouter: tool %q of server %q has no risk class (set risk or default_risk)`.
      Then `toolrouter.ValidateTool(tool)`; on error close all and return it.
   4. Every key in `conn.Config.Risk` must be a tool the server offered.
      Otherwise: `mcprouter: server %q has no tool %q (listed in risk)`. This
      catches typos in config.
3. Duplicate namespaced names cannot happen (server names are unique); still
   check and return `mcprouter: duplicate tool %q` if it does.
4. Keep tools in server order, then the order the server listed them.

### `Call`

1. `e, ok := r.byName[call.Name]`; if not: `fmt.Errorf("%w: %q", toolrouter.ErrUnknownTool, call.Name)`.
2. `args := call.Arguments`; if empty, `json.RawMessage("{}")`.
3. `start := r.now()`.
4. `res, err := e.session.CallTool(ctx, &mcp.CallToolParams{Name: e.tool, Arguments: args})`.
5. If `err != nil`: return `toolrouter.Result{}, fmt.Errorf("mcprouter: call %s: %w", call.Name, err)`.
6. `out := toResult(res)`; `out.Duration = r.now().Sub(start)`; return `out, nil`.

### `toResult` (file `result.go`)

```go
func toResult(res *mcp.CallToolResult) toolrouter.Result
```

1. For each item in `res.Content`, in order:
   - `*mcp.TextContent` → its `Text`.
   - anything else → `fmt.Sprintf("[%s content omitted]", kind)` where `kind`
     is the type name without package and pointer, lower case, e.g.
     `*mcp.ImageContent` → `imagecontent`. Use
     `strings.ToLower(strings.TrimPrefix(fmt.Sprintf("%T", item), "*mcp."))`.
2. Join the pieces with `"\n"` → `Output`.
3. If `Output` is empty and `res.StructuredContent != nil`, set `Output` to its
   `json.Marshal` (ignore marshal errors: leave empty).
4. `IsError = res.IsError`; `ExitCode = 0`.

### `Close`

Close every session (in reverse order); return `errors.Join` of the errors.
Calling `Close` twice must not panic: set `r.sessions = nil` after closing.

## Out of scope

- HTTP/SSE transports (stdio only).
- Restarting a crashed server.
- Tools changing at runtime (`ToolListChangedHandler`).
- Output capping for the model (the harness calls `toolrouter.ForModel`).

## Pitfalls

- **Never write to stdout in a stdio MCP server or its test mode** — stdout is the protocol. Logs go to stderr.
- `exec.CommandContext` would kill the servers when `Start`'s ctx ends; use `exec.Command`.
- `TestMain` must call `os.Exit(m.Run())` in the normal path, or no tests run.
- Close sessions you already opened when a later server fails, or subprocesses leak.
- Map iteration order is random: when building `cmd.Env` from the map, sort keys first; in `connectTest`, sort server names.
- The SDK validates arguments against the schema: a "failed" call because of bad arguments is a tool error (`IsError`), not a Go error.
