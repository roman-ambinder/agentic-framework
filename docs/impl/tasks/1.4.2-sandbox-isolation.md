# 1.4.2 — Sandbox limits, network, workspace

Size: M · Depends on: 1.4.1 · Branch: `task/1.4.2-sandbox-isolation` · PR title: `1.4.2: sandbox isolation and workspace copy`

## Goal

After this task a Docker sandbox:

- has **no network** unless `Spec.Network` is true;
- is limited to `Spec.CPUs` CPUs and `Spec.MemoryBytes` memory (no swap) and 512 processes;
- runs every process as the **non-root user 65532:65532**, with all Linux
  capabilities dropped and `no-new-privileges`;
- gets **only** `Spec.Env` (plus `HOME=/tmp` if not set) as its environment,
  never anything from the host process;
- gets a **copy** of `Spec.WorkspaceDir` at `/workspace`, owned by 65532 and
  writable; the host directory is never mounted and never changed.

## Design

### Why copy instead of bind-mount

A bind mount would let a command in the sandbox change or delete files in the
host directory (and follow symlinks out of it). Copying in means the host
copy is never touched; results come back only through `CopyOut`, which the
caller turns into a diff.

### Why the root filesystem is NOT read-only

`ReadonlyRootfs` would block `CopyToContainer` and the Go build cache in
`/tmp`. Isolation from the host comes from: no mounts, no network, non-root,
no capabilities, `no-new-privileges`, process and memory limits.
Write this reasoning as a comment above `hostConfig`.

### Constants (`internal/sandbox/sandbox.go`)

```go
// SandboxUID and SandboxGID are the user every sandbox process runs as.
const (
	SandboxUID = 65532
	SandboxGID = 65532
)

// PidsLimit caps the number of processes in a sandbox.
const PidsLimit = 512

// MaxWorkspaceBytes caps the total size of files copied into a sandbox.
const MaxWorkspaceBytes = 512 << 20 // 512 MiB

// DefaultHome is HOME inside a sandbox unless Spec.Env sets it.
const DefaultHome = "/tmp"
```

### `WorkspaceTar` (`internal/sandbox/workspace.go`)

```go
// WorkspaceTar returns a tar archive that, extracted at "/", creates
// /workspace with the contents of dir. dir == "" gives an archive with only
// the empty /workspace directory. Every entry is owned by uid:gid.
// Symlinks and special files are skipped (and counted in skipped).
// It returns an error wrapping ErrInvalidSpec if the regular files add up
// to more than maxBytes.
func WorkspaceTar(dir string, uid, gid int, maxBytes int64) (archive []byte, skipped int, err error)
```

Algorithm:

1. Write a directory header: `Name: "workspace/"`, `Typeflag: tar.TypeDir`,
   `Mode: 0o755`, `Uid: uid`, `Gid: gid`, `ModTime`: fixed `time.Unix(0, 0)`.
2. If `dir == ""`, close the writer and return.
3. `filepath.WalkDir(dir, ...)` in lexical order (WalkDir already is):
   - skip `dir` itself (already written);
   - `rel := filepath.ToSlash(filepath.Rel(dir, path))`, name = `"workspace/" + rel`;
   - directory → header `TypeDir`, name with trailing `/`, mode `0o755`;
   - regular file → header `TypeReg`, mode = `info.Mode().Perm()`, size,
     then copy the content; add size to a running total and fail with
     `fmt.Errorf("%w: workspace is larger than %d bytes", ErrInvalidSpec, maxBytes)`
     when it exceeds `maxBytes`;
   - anything else (symlink, socket, device) → `skipped++`, do not descend.
4. All headers: `Uid: uid, Gid: gid`, `Uname`/`Gname` empty, `ModTime` = the file's mod time.
5. Close the writer; return the bytes.

### Docker `Create` changes (`internal/sandbox/docker/docker.go`)

Replace the `// Applied in task 1.4.2.` placeholders. New order inside `Create`:

1. `spec.Validate()`.
2. Ensure the image (unchanged from 1.4.1).
3. `archive, skipped, err := sandbox.WorkspaceTar(spec.WorkspaceDir, sandbox.SandboxUID, sandbox.SandboxGID, sandbox.MaxWorkspaceBytes)`.
   If `skipped > 0`, keep the number: return it to no one, but put it in the
   container label `adlc.workspace_skipped` so it can be inspected.
4. `ContainerCreate` with `containerConfig(spec)` and `hostConfig(spec)` (below).
5. `CopyToContainer(ctx, id, client.CopyToContainerOptions{DestinationPath: "/", Content: bytes.NewReader(archive), CopyUIDGID: true})`.
   This runs **before** `ContainerStart` (copying into a created container is allowed).
6. `ContainerStart`.
7. On any error after step 4, force-remove the container before returning.

```go
func containerConfig(spec sandbox.Spec) *container.Config {
	return &container.Config{
		Image:  spec.Image,
		Cmd:    []string{"sh", "-c", "while :; do sleep 3600; done"},
		User:   fmt.Sprintf("%d:%d", sandbox.SandboxUID, sandbox.SandboxGID),
		Env:    envList(withDefaults(spec.Env)), // adds HOME=/tmp if missing
		Labels: labels(spec),
		// No WorkingDir: Docker would create /workspace owned by root.
		// /workspace comes from the archive; Exec sets WorkingDir per command.
	}
}

func hostConfig(spec sandbox.Spec) *container.HostConfig {
	init := true
	pids := int64(sandbox.PidsLimit)
	hc := &container.HostConfig{
		Init:        &init,
		CapDrop:     []string{"ALL"},
		SecurityOpt: []string{"no-new-privileges:true"},
	}
	hc.PidsLimit = &pids
	if !spec.Network {
		hc.NetworkMode = container.NetworkMode("none")
	}
	if spec.CPUs > 0 {
		hc.NanoCPUs = int64(spec.CPUs * 1e9)
	}
	if spec.MemoryBytes > 0 {
		hc.Memory = spec.MemoryBytes
		hc.MemorySwap = spec.MemoryBytes // equal to Memory = no swap
	}
	return hc
}
```

(`NanoCPUs`, `Memory`, `MemorySwap`, `PidsLimit` are fields of the embedded
`container.Resources`; `NetworkMode`, `CapDrop`, `SecurityOpt`, `Init` are
fields of `container.HostConfig` — verified in moby api v1.57.0.)

Remove `WorkingDir` from the 1.4.1 config (comment above explains why). `Exec`
still passes `WorkingDir: sandbox.WorkspacePath` in `ExecCreateOptions`.

`envList` must build the list **only** from the map it is given. Never call
`os.Environ()` anywhere in `internal/sandbox`.

### `sandboxtest.Host`

Make `Host.Create` add `HOME` like Docker does (`withDefaults`), so code
tested on `Host` sees the same environment shape. Nothing else changes in
`Host`: it still has no isolation.

## Out of scope

- Seccomp/AppArmor profiles beyond Docker's defaults; user namespaces.
- Disk quotas for `/workspace` or `/tmp`.
- An egress allow-list (network is all or nothing here).
- Turning `CopyOut` output into a diff (task 1.8 does that).
- Snapshots / restoring a sandbox (not planned for M1).

## Pitfalls

- Setting `Config.WorkingDir` makes Docker create `/workspace` owned by root;
  the non-root user then cannot write. Do not set it.
- Without `CopyUIDGID: true`, Docker ignores the archive's owners and
  creates files as root.
- `MemorySwap` must equal `Memory`, otherwise the process swaps instead of
  being killed and the memory test hangs or passes for the wrong reason.
- `NanoCPUs` and `CPUQuota` must not both be set; use only `NanoCPUs`.
- The image's own `ENV` lines (e.g. `PATH`) still apply; that is fine. What
  must never happen is copying the **host** environment.
- `busybox` and Debian-based images both have `/tmp` with mode 1777, so
  `HOME=/tmp` is writable for 65532. An image without a writable `/tmp` is
  not supported.
