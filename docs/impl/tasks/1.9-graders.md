# 1.9 — Graders and report

Size: M · Depends on: 1.8 · Branch: `task/1.9-graders` · PR title: `1.9: outcome and trajectory graders, pass@1 summary`

## Goal

After this task every eval result carries a `Grade`: outcome checks (hidden
tests, build, other tests, vet) run in the grading sandbox, plus trajectory
numbers (steps, tool calls, wasted calls, denials, cost, time) taken from the
run's `RunState`. The report gets a per-provider `Summary` with pass@1 overall
and per difficulty, and `adlc eval-report FILE` prints the table from a saved
report. These numbers feed gate G1.

## Design

### Types (`grade.go`)

```go
// Check is the result of one command run in the grading sandbox.
type Check struct {
	OK       bool   `json:"ok"`
	ExitCode int    `json:"exit_code"`
	TimedOut bool   `json:"timed_out"`
	Output   string `json:"output,omitempty"` // last 4 KiB of stdout+stderr, only when !OK
}

// Grade is everything measured about one result.
type Grade struct {
	Solved bool `json:"solved"` // HiddenPass && Build.OK && OtherTests.OK

	// Outcome
	HiddenPass bool  `json:"hidden_pass"` // Result.Hidden.AllPassed()
	Build      Check `json:"build"`       // go build ./...
	OtherTests Check `json:"other_tests"` // go test -count=1 -skip '^(hidden...)$' ./...
	Vet        Check `json:"vet"`         // go vet ./...  (reported, not part of Solved)
	TestFilesChanged int `json:"test_files_changed"` // ChangedFiles ending in "_test.go"
	FilesChanged     int `json:"files_changed"`

	// Trajectory (zero when the run never started)
	Steps        int   `json:"steps"`         // RunState.Step
	ModelCalls   int   `json:"model_calls"`
	ToolCalls    int   `json:"tool_calls"`
	WastedCalls  int   `json:"wasted_calls"`  // RunState.ToolErrors
	Denials      int   `json:"denials"`
	InputTokens  int64 `json:"input_tokens"`
	OutputTokens int64 `json:"output_tokens"`
	CacheReadTokens int64 `json:"cache_read_tokens"`
	USDMicros    int64 `json:"usd_micros"`
	WallClockMS  int64 `json:"wall_clock_ms"` // LastEventAt - StartedAt
}
```

`Result` gets a new field `Grade *Grade \`json:"grade,omitempty"\`` (nil when
`Result.Error != ""`). `Result.Solved()` becomes `r.Error == "" && r.Grade != nil && r.Grade.Solved`.

### Commands (all run from `/workspace` in the grading sandbox, timeout `bug.Timeout` each)

| Check | Command |
|-------|---------|
| Build | `go build ./...` |
| Vet | `go vet ./...` |
| OtherTests | `go test -count=1 -skip '^(A|B)$' ./...` where `A|B` = `strings.Join(bug.HiddenTests, "\|")` |
| Hidden | `HiddenTestArgs(bug)` (unchanged from 1.8) |

Add `func OtherTestsArgs(bug Bug) []string` returning exactly
`[]string{"go", "test", "-count=1", "-skip", "^(" + strings.Join(bug.HiddenTests, "|") + ")$", "./..."}`.

`OtherTests` includes tests the agent added (that is intended: an agent that
added a broken test did not finish the job). It also includes the fixture's
own tests, so it catches fixes that break something else.

A `Check` is `OK` when `ExitCode == 0 && !TimedOut`.

### Changes to `RunOne` (1.8 step numbers)

Between steps 12 and 13 of 1.8, in the same grading sandbox `h2`, run Build,
Vet and OtherTests in that order (each even if the previous failed). Then after
step 13: `res.Grade = gradeOf(result, bug, checks)`. An `Exec` error (not a
non-zero exit — an error returned by `Exec`) sets `Result.Error = "grade: …"`
and leaves `Grade` nil.

`trajectory(state *eventlog.RunState) Grade` fills the trajectory fields
(nil state → zeros); `WallClockMS` is 0 if either time is zero.

### Summary (`summary.go`)

```go
// Bucket counts results.
type Bucket struct {
	Runs    int     `json:"runs"`
	Solved  int     `json:"solved"`
	PassAt1 float64 `json:"pass_at_1"` // Solved / Runs, 0 when Runs == 0; rounded to 3 decimals
}

// ProviderSummary aggregates one provider's results.
type ProviderSummary struct {
	Bucket                                     // all difficulties
	ByDifficulty  map[Difficulty]Bucket `json:"by_difficulty"` // always has easy, medium, hard keys
	Errors        int              `json:"errors"`          // results with Error != ""; NOT counted in Runs
	MedianUSDMicrosSolved int64    `json:"median_usd_micros_solved"`
	MedianStepsSolved     float64  `json:"median_steps_solved"`
	TotalUSDMicros        int64    `json:"total_usd_micros"` // all graded results
	StopReasons   map[string]int   `json:"stop_reasons"`    // stop reason name → count, graded results
}

// Summary aggregates a report.
type Summary struct {
	ByProvider map[string]ProviderSummary `json:"by_provider"`
}

// Summarize computes the summary of results.
func Summarize(results []Result) Summary
```

Rules:
- Results with `Error != ""` count only in `Errors`; they are not runs. (An infrastructure failure says nothing about the agent.)
- Medians are over **solved** results only. `median` of an even count = mean of the two middle values (for `int64` money: integer mean, rounded down). Empty → 0.
- `Report` gets `Summary Summary \`json:"summary"\``.

### Table (`PrintTable`, replaces 1.8's format)

```
BUG                     PROVIDER   RESULT  STOP          STEPS  TOOLS  WASTED  COST    SECONDS
stock-negative-reserve  anthropic  solved  COMPLETED     23     41     2       $0.42   84
...

anthropic  solved 6/10 (pass@1 0.600)  easy 3/3  medium 2/4  hard 1/3  median $0.42  median steps 23  total $4.10  errors 0
openai     solved 5/10 (pass@1 0.500)  easy 3/3  medium 2/4  hard 0/3  median $0.31  median steps 30  total $3.02  errors 1
```

Money: `fmt.Sprintf("$%.2f", float64(micros)/1e6)`. `RESULT`: `solved`,
`failed`, or `error`. For `error` rows, `STEPS`…`COST` print `-`. Summary lines
sorted by provider. If any provider has `errors > 0`, add a final line:
`note: results with errors are excluded from pass@1`.

`PrintTable(w io.Writer, rep Report)` — signature changes to take the report
(it needs the summary). Update the call in `eval.go`.

### `adlc eval-report FILE`

Reads a report JSON written by `adlc eval` and calls `PrintTable`. Error if the
file is missing or not a report: `read report <path>: <err>`.

## Pitfalls

- `go test -skip` needs Go 1.20 or newer; the sandbox image is `golang:1.26`, fine. Do not use `-run` with a negative pattern instead (Go regexps have no negative lookahead).
- Run the three checks even when an earlier one failed: each is reported separately.
- Do not count infrastructure errors as failed runs; that would mix Docker problems into the agent's score.
- `PassAt1` is rounded for output only; keep the counts so nothing is lost.
- Medians over solved results only: the cost of a failed attempt is in `TotalUSDMicros`.
