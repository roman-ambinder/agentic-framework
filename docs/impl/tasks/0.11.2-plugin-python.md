## Goal

After this task, the repository has a working hook plugin written in Python
(`examples/plugins/python-hook`). It denies tool calls whose name matches a
regular expression. A Go integration test proves the language boundary works:
a harness run on the fake model is stopped by the Python hook. This keeps the
core honest about not depending on Go-only behaviour.

## Design

### Versions (verified to exist and to work together on Python 3.13)

`requirements.txt`, exactly:

```
grpcio==1.85.1

protobuf==7.36.2
```

### Generated Python code is not committed

The Python stubs are generated by `make python-hook-setup` into
`examples/plugins/python-hook/gen/`, which is git-ignored. Reason: committed
stubs would go stale silently when `plugin.proto` changes; generating them in
the test setup makes staleness impossible.

`examples/plugins/python-hook/.gitignore`:

```
.venv/
gen/
__pycache__/
```

### Makefile targets (exact)

```make
PYHOOK := examples/plugins/python-hook

python-hook-setup: ## Create the Python hook plugin's venv and generate its stubs
	python3 -m venv $(PYHOOK)/.venv
	$(PYHOOK)/.venv/bin/pip install --quiet -r $(PYHOOK)/requirements.txt
	mkdir -p $(PYHOOK)/gen
	$(PYHOOK)/.venv/bin/python -m grpc_tools.protoc -I contracts/proto \
	  --python_out=$(PYHOOK)/gen --grpc_python_out=$(PYHOOK)/gen \
	  adlc/v1/events.proto adlc/v1/plugin.proto

test-plugin-python: python-hook-setup ## Run the Python plugin integration test
	go test -tags plugin_python -count=1 -run 'Python' ./internal/plugin/
```

Add both names to `.PHONY`. Do not add them to `ci:` (the main CI job has no Python setup step); the separate
CI job below runs them.

Generation produces `gen/adlc/v1/events_pb2.py`, `plugin_pb2.py`, `plugin_pb2_grpc.py` (and an empty
`events_pb2_grpc.py`). Python imports them as `from adlc.v1 import plugin_pb2, plugin_pb2_grpc, events_pb2`
once `gen/` is on `sys.path` (no `__init__.py` files are needed).

### `hook_plugin.py` behaviour

Configuration, all through environment variables:

| Variable | Meaning |
|----------|---------|
| `ADLC_PLUGIN_SOCKET` | Unix socket path to listen on (set by the launcher). Required. |
| `ADLC_HOOK_DENY_PATTERN` | Python regular expression. A tool call whose `info.call.name` matches it with `re.fullmatch` is denied. Unset or empty → allow everything. |
| `ADLC_HOOK_LOG` | Optional file path. Each `PostTool` appends one JSON line `{"tool": <name>, "is_error": <bool>, "exit_code": <int>}`. |

Exact behaviour:
1. Put `<directory of this file>/gen` first on `sys.path`, then import the generated modules.
2. If `ADLC_PLUGIN_SOCKET` is unset: print `ADLC_PLUGIN_SOCKET is not set` to stderr, exit code 2.
3. Compile the pattern once at start. Invalid pattern: print `invalid ADLC_HOOK_DENY_PATTERN: <error>` to stderr, exit code 2.
4. `PreTool`: if the pattern is set and `re.fullmatch(pattern, request.info.call.name)` → return
   `PreToolResponse(decision=events_pb2.DECISION_DENY, reason=f"tool {name} matches deny pattern {pattern_text}")`;
   otherwise `PreToolResponse(decision=events_pb2.DECISION_ALLOW)`.
5. `PostTool`: if `ADLC_HOOK_LOG` is set, append the JSON line (open in append mode, write, close). Return `PostToolResponse()`.
6. Server: `grpc.server(concurrent.futures.ThreadPoolExecutor(max_workers=4))`,
   `plugin_pb2_grpc.add_HookServiceServicer_to_server(Hook(), server)`,
   `server.add_insecure_port("unix:" + socket_path)`, `server.start()`.
7. On `SIGTERM` or `SIGINT`: `server.stop(grace=1)` and exit 0. Otherwise `server.wait_for_termination()`.
8. No other output on stdout (stderr is fine for errors).

```python
class Hook(plugin_pb2_grpc.HookServiceServicer):
    def __init__(self, pattern, pattern_text, log_path): ...
    def PreTool(self, request, context): ...
    def PostTool(self, request, context): ...


def main() -> int: ...

    sys.exit(main())
```

### Go integration test (`internal/plugin/python_test.go`)

First line: `//go:build plugin_python`. Package `plugin`.

Helper:

```go
// pythonHook returns a Config that runs the example plugin, or skips the
// test if `make python-hook-setup` has not been run.
func pythonHook(t *testing.T, env ...string) Config {
	t.Helper()
	root := repoRoot(t) // walk up from the working directory to the dir containing go.mod
	dir := filepath.Join(root, "examples", "plugins", "python-hook")
	py := filepath.Join(dir, ".venv", "bin", "python")
	if _, err := os.Stat(py); err != nil {
		t.Skip("python hook not set up; run `make python-hook-setup`")
	}
	if _, err := os.Stat(filepath.Join(dir, "gen", "adlc", "v1", "plugin_pb2.py")); err != nil {
		t.Skip("python stubs missing; run `make python-hook-setup`")
	}
	return Config{Name: "python-hook", Command: []string{py, filepath.Join(dir, "hook_plugin.py")}, Env: env}
}
```

Tests:
- `TestPythonHookDeniesMatchingTool` — `ADLC_HOOK_DENY_PATTERN=fs__write_.*`; `PreTool` for `fs__write_file` →
  `HookDecision.Deny == true`, `Reason` contains `matches deny pattern`.
- `TestPythonHookAllowsOtherTools` — same pattern; `PreTool` for `fs__read_file` → `HookDecision.Deny == false`.
- `TestPythonHookPostToolLog` — `ADLC_HOOK_LOG=<tmp>/log.jsonl`; after `PostTool` for `fs__read_file` with
  `IsError: true, ExitCode: 3`, the file has one line that decodes to `{"tool":"fs__read_file","is_error":true,"exit_code":3}`.
- `TestPythonHookStopsHarnessRun` — the end-to-end check:
  1. Fake model: one turn with a tool call `{ID: "t1", Name: "fs__write_file", Arguments: {"path":"x","content":"y"}}`
     and `Finish: FINISH_REASON_TOOL_USE`, then a second turn with text `done` and `FINISH_REASON_END_TURN`.
  2. Static router with `fs__write_file` (risk `WRITE_LOCAL`) whose `Func` fails the test if called.
  3. Policy `policy.AllowAll{}`; `Hooks: []harness.Hook{proc}` where `proc` is the started Python plugin with
     `ADLC_HOOK_DENY_PATTERN=fs__write_.*`.
  4. Event log: `eventlog.Open` on a temp file.
  5. `harness.Run`. Assert: final state `StopReason == STOP_REASON_DENIED`; the log contains a `policy_decided`
     event with `source == DECISION_SOURCE_HOOK`, `decision == DECISION_DENY` and `rule_id == "hook:python-hook"`;
     the tool `Func` was never called.
- `TestPythonHookBadPattern` — `ADLC_HOOK_DENY_PATTERN=(` → `Start` fails with `errors.Is(err, ErrExited)` and the
  error text contains `invalid ADLC_HOOK_DENY_PATTERN`.

## Pitfalls

- Use `re.fullmatch`, not `re.match`: `fs__write_.*` must not deny `xfs__write_file`, and a pattern without `.*`
  must match the whole name.
- `server.add_insecure_port` returns 0 on failure instead of raising: if it returns 0, print an error and exit 1.
- The `gen/` directory must be first on `sys.path`, before any installed package named `adlc`.
- Never commit `.venv/` or `gen/`; check `git status` before committing.
- `python3 -m venv` needs the `venv` module; on Debian/Ubuntu it is the `python3-venv` package. If it is missing
  locally, the Go test skips; CI installs it through `actions/setup-python`.
