# 1.7 — Resume a crashed run

Size: M · Depends on: 0.5.4, 1.4.2 · Branch: `task/1.7-resume` · PR title: `1.7: resume a run that stopped without run_completed`

## Goal

If the `adlc` process dies in the middle of a run (killed, machine slept,
crash), the run's log ends without `run_completed`. After this task,
`adlc resume RUN_ID` continues such a run from where it stopped:

- it refuses runs that finished, are paused for approval, or whose last
  checkpoint does not match the log;
- it closes whatever was in flight when the process died, by **appending**
  events (the log is append-only; nothing is removed);
- it continues the normal harness loop, so the model sees what happened and
  carries on.

## Design

### New event kind (`events.proto`)

Add to the `payload` oneof, after `error_occurred = 21`:

```proto
    RunResumed run_resumed = 22;
```

and the message (put it in the "Run lifecycle" section):

```proto
// RunResumed is written when a run that stopped without run_completed is
// continued by `adlc resume`.
message RunResumed {
  // Step the resumed run continues with.
  uint32 next_step = 1;
  // seq of the last checkpoint that was verified, 0 if the run had none.
  uint64 verified_checkpoint_seq = 2;
  // Tool calls closed as abandoned because the process died during them.
  uint32 abandoned_tool_calls = 3;
  // Why the run is resumed, for people reading the log.
  string reason = 4;
}
```

Run `make proto`, then `make proto-breaking` (must pass: adding a field is allowed).

### Fold (`internal/eventlog/fold.go`)

Add a case that changes **nothing** in `RunState`:

```go
case *adlcv1.Event_RunResumed:
	// Allowed only while running (the general checks above already reject it
	// after a finish, and while paused only approval_resolved is allowed).
```

Do **not** add a field to `RunState`: that would change `Digest()` for every
existing log, and checkpoints written before this change would no longer
verify.

Add `run_resumed` samples to `contracts/contracts_test.go` (`samplePayloads`)
and to `TestEveryKindIsHandled` in `internal/eventlog/fold_test.go` (put it
after `error_occurred`, before `run_completed`).

### Errors (`internal/harness/resume.go`)

```go
var (
	// ErrRunFinished: the run already has a final run_completed.
	ErrRunFinished = errors.New("harness: run already finished")
	// ErrRunPaused: the run is waiting for an approval; resolve it instead.
	ErrRunPaused = errors.New("harness: run is waiting for approval")
	// ErrCheckpointMismatch: the log does not match its last checkpoint.
	ErrCheckpointMismatch = errors.New("harness: checkpoint does not match the log")
	// ErrAgentMismatch: Config.AgentVersion differs from the run's run_started.
	ErrAgentMismatch = errors.New("harness: agent version differs from the run")
)

// Resume continues the run cfg.RunID, which must exist in deps.Log and must
// have stopped without a final run_completed. cfg.Task is ignored: the task
// comes from the run's run_started event. Unknown run → error wrapping
// eventlog.ErrRunNotFound.
func Resume(ctx context.Context, cfg Config, deps Deps) (*eventlog.RunState, error)
```

### Checkpoint digest definition

`Resume` relies on how task 0.5.4 writes checkpoints. The definition is:

> `checkpoint.state_digest` = `RunState.Digest()` of the state folded from
> **all events before** the checkpoint event (seq < checkpoint seq).

Read `internal/harness` to confirm 0.5.4 does exactly this. If it computes
the digest differently, verify the way it writes and state the difference in
the PR description; do not change how checkpoints are written.

### Resume algorithm

```
Resume(ctx, cfg, deps):
 1. Apply the same defaults and validation as Run, except cfg.Task may be empty.
 2. events := deps.Log.Read(ctx, cfg.RunID, 0)
    len(events) == 0 → fmt.Errorf("%w: %q", eventlog.ErrRunNotFound, cfg.RunID)
 3. state, err := eventlog.Fold(events); err → fmt.Errorf("harness: resume: %w", err)
 4. state.Status == Finished → ErrRunFinished; Paused → ErrRunPaused
 5. cfg.AgentVersion != state.AgentVersion →
        fmt.Errorf("%w: run has %q, config has %q", ErrAgentMismatch, state.AgentVersion, cfg.AgentVersion)
 6. Verify the last checkpoint (if state.LastCheckpoint != nil):
        cp := state.LastCheckpoint
        before, _ := eventlog.Fold(events[:cp.Seq-1])
        d, _ := before.Digest()
        d != cp.StateDigest → fmt.Errorf("%w: checkpoint at seq %d", ErrCheckpointMismatch, cp.Seq)
 7. r := recorder seeded with events and state (see "Recorder seeding")
 8. Work out what was in flight (see "Recovery cases") and append, in this order:
      a. run_resumed{next_step, verified_checkpoint_seq: cp.Seq or 0,
                     abandoned_tool_calls: n, reason: "process stopped without run_completed"}
      b. the recovery events for the case
 9. If the case ended the run (cases E, G and F), return &r.state, nil.
10. Continue the normal loop with step = next_step (see "Loop entry point").
```

`next_step` = (number of `model_call_completed` events in the log) + 1.

### Recovery cases

Look at the events **after the last `model_call_completed`** (or after
`run_started` if there is none) and at `state`. Exactly one case applies;
check them in the order of the table (E, G, F, A, B, C, D):

| Case | Situation | Append after `run_resumed` | Then |
|------|-----------|----------------------------|------|
| E | `state.PendingApprovals` not empty (died after `approval_requested`, before `run_completed`) | `run_completed{stop_reason: AWAITING_APPROVAL}` | return (paused) |
| G | last event is `policy_decided` with `DENY` (died before writing `run_completed`) | `run_completed{stop_reason: DENIED, detail: "rule <rule_id>: <reason>"}` (same text as the loop writes) | return |
| F | last `model_call_completed` has no tool calls and `finish_reason == END_TURN`, nothing after it but maybe a checkpoint | `run_completed{COMPLETED, result: its text}` | return |
| A | `state.PendingToolCalls` not empty (died during a tool call) | for each pending id, in order: `tool_call_completed{call_id, is_error: true, output: AbandonedOutput}` with `parent_seq` = seq of its `tool_call_requested` | then case B for the rest of the calls of that response |
| B | the last `model_call_completed` has tool calls that have **no** `tool_call_requested` | for each such call, in the response's order: `tool_call_requested{call, risk_class, server}` (look up risk and server in `deps.Tools.Tools()` by name; unknown → `UNSPECIFIED`, `""`), then `tool_call_completed{is_error: true, output: NotRunOutput}` | continue |
| C | last event is `model_call_started` or `model_call_failed` (died during a model call) | nothing | continue (the model call is made again) |
| D | anything else (died after a complete step) | nothing | continue |

```go
// AbandonedOutput is the tool result for a call that was running when the
// process died. The call may or may not have taken effect.
const AbandonedOutput = "abandoned: the run stopped while this tool call was running; it may or may not have taken effect. Check before repeating it."

// NotRunOutput is the tool result for a call that was never started.
const NotRunOutput = "not run: the run stopped before this tool call started. Call it again if it is still needed."
```

`run_resumed.abandoned_tool_calls` = number of `AbandonedOutput` plus
`NotRunOutput` results appended.

Why case B matters: an assistant message with tool calls but no tool results
is rejected by model providers, so every requested tool call must get a result.

### Recorder seeding

Add to `recorder` (0.5.1):

```go
// newRecorderFrom returns a recorder that already holds events (as read from
// the log) and the state folded from them.
func newRecorderFrom(ctx context.Context, log Log, runID, agentID string, events []*adlcv1.Event, state eventlog.RunState) *recorder
```

### Loop entry point (refactor in `loop.go`)

Move the body of `Run`'s `for step := 1; ; step++` loop into a function
both `Run` and `Resume` call:

```go
// loop runs steps from firstStep until the run stops.
func (h *runner) loop(ctx context.Context, firstStep int) (*eventlog.RunState, error)
```

where `runner` holds `cfg`, `deps`, the `recorder`, the tool list and
`byName` map (whatever `Run` built before the loop). `Run` becomes:
defaults/validation → new recorder → `run_started` → `loop(ctx, 1)`.
Behaviour of `Run` must not change: all existing harness tests must pass
unchanged. If the 0.5.x code is shaped differently, make the smallest
change that gives one shared loop function; describe it in the PR.

### Budgets on resume

Every budget counter the loop checks (task 0.5.2) must come from the folded
state, never start from zero, so a resumed run cannot exceed its budget.
Wall clock: the time already used is `state.LastEventAt.Sub(state.StartedAt)`;
the resumed run may use `max_wall_clock − used` from the moment it resumes.
Implement this as a `startedAt` value in `runner` that `Run` sets to
`deps.Now()` and `Resume` sets to `deps.Now().Add(-used)`; the wall-clock
check uses `deps.Now().Sub(h.startedAt)`.

### Transcript

`Transcript` ignores `run_resumed` (add it to the kinds that create no
message). The recovery results from cases A and B appear as ordinary tool
results, so the model sees them.

### `adlc resume` (`internal/cli/resume.go`)

```
adlc resume RUN_ID --agent agent.yaml [same flags as `adlc run`, except --task]
```

1. If `internal/cli/run.go` builds `Config`/`Deps` inline, first extract it
   into `func buildRun(ctx context.Context, opts runOptions, runID string) (harness.Config, harness.Deps, func() error, error)`
   (the last return closes everything it opened). `adlc run` must behave as before.
2. `resume` loads the agent config, calls `buildRun` with the given run id.
3. **Sandboxed runs:** if any tool command in the agent config contains
   `sandbox.SandboxIDPlaceholder`, the run used a sandbox. Find it with
   `docker.FindByRunID(ctx, runID)`:
   - exactly one → probe it with `Exec(ctx, h, []string{"true"}, 10*time.Second)`;
     if the probe errors, fail with
     `sandbox for run %q is not running; its workspace changes cannot be recovered. Start a new run.`
   - none → same message; more than one → `found %d sandboxes for run %q; remove the extra ones with docker rm`.
   - expand tool commands with `sandbox.ExpandArgs` using that handle.
4. `harness.Resume(ctx, cfg, deps)`; print the result exactly as `adlc run` does.
5. Exit codes: same as `adlc run`; refusal errors (`ErrRunFinished`,
   `ErrRunPaused`, `ErrCheckpointMismatch`, `ErrAgentMismatch`, not found) exit 1
   with `Error: <message>`.

## Out of scope

- Resolving approvals and continuing a paused run (control plane, M2).
- Restoring a sandbox whose container is gone (no snapshots in M1); resume
  refuses instead.
- Undoing side effects of abandoned tool calls.
- Resuming several runs at once, or automatically on start-up.

## Pitfalls

- Never delete or rewrite events to "clean up" a crashed log. Recovery only appends.
- Fold must accept `run_resumed` only while running; do not special-case it
  elsewhere.
- Adding a field to `RunState` changes every digest. Don't.
- `events[:cp.Seq-1]` is correct because seq starts at 1 (event with seq s is `events[s-1]`).
- In case A, give each abandoned result the `parent_seq` of its own
  `tool_call_requested`, not of `run_resumed`.
- The helper process must not run when the whole test suite runs: it skips
  unless `ADLC_CRASH_HELPER=1`.
- SQLite in WAL mode keeps every committed append across a `SIGKILL`; if a
  crash test finds fewer events than `n`, that is a real bug, not flakiness.
- Building the fake for the resumed part: count `model_call_completed`, not
  `model_call_started` (a started call that never completed consumed no
  recorded turn).
