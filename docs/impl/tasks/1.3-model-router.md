# 1.3 — Model router and fallback

Size: S · Depends on: 1.1, 1.2 · Branch: `task/1.3-model-router` · PR title: `1.3: model router with provider fallback`

## Goal

A `model.Adapter` in `internal/model/router` that holds an ordered list of
candidates (adapter + model id). Each call goes to the first candidate; if
that fails with a retryable error, the router tries the next one at once. The
response says which provider and model actually answered, so the harness can
record it and price it correctly. Agent config gets a `fallbacks` list.

## Design

### Contract changes (put this text into `interfaces.md` in the same PR)

In §2, `Response` gets two fields at the end:

```go
	// Provider and Model that produced this response. Adapters set
	// Provider to their Provider() value and Model to the request's model.
	// A router sets them to the candidate that answered.
	Provider string
	Model    string
```

Every existing adapter (`fake`, `anthropic`, `openai`) must set both. Add one
line to each adapter's `Generate`, and one assertion to one existing test per
adapter.

In §6, `harness.Config` gets:

```go
	// Prices per model id. When the response's Model is in the map, that
	// price is used; otherwise Price.
	Prices map[string]model.Price
```

In `events.proto`, `ModelCallCompleted` gets (additive; does not break
compatibility):

```proto
  // Provider and model that actually answered (differs from
  // model_call_started when a router fell back).
  string provider = 8;
  string model = 9;
```

### Router API

```go
package router

// Candidate is one adapter plus the model id to ask it for.
type Candidate struct {
	Adapter model.Adapter
	Model   string
}

// Router tries candidates in order. It implements model.Adapter.
type Router struct {
	candidates []Candidate
}

// ErrNoCandidates is returned by New for an empty list.
var ErrNoCandidates = errors.New("router: no candidates")

func New(candidates ...Candidate) (*Router, error)

func (r *Router) Provider() string // "router"
func (r *Router) Generate(ctx context.Context, req *model.Request) (*model.Response, error)
func (r *Router) CountTokens(ctx context.Context, req *model.Request) (int64, error)
func (r *Router) Capabilities() model.Caps
```

### Generate algorithm

```
1. var last error
2. for i, c := range r.candidates:
   a. if err := ctx.Err(); err != nil: return nil, err
   b. creq := *req; creq.Model = c.Model           // shallow copy; never modify req
   c. resp, err := c.Adapter.Generate(ctx, &creq)
   d. if err == nil:
          resp.Provider = c.Adapter.Provider()
          resp.Model = c.Model
          return resp, nil
   e. if !model.IsRetryable(err): return nil, err    // e.g. 400: would fail the same way
   f. last = err                                      // try the next candidate
3. return nil, fmt.Errorf("router: all %d candidates failed: %w", len(r.candidates), last)
```

Rules, stated explicitly:
- Every call starts at candidate 0 (the primary). The router keeps no state.
- Fallback happens only on retryable errors. A `REFUSAL` finish is a normal
  response and is returned as-is (no fallback).
- The router does not sleep or retry the same candidate. The harness's retry
  policy (task 0.5.3) wraps the whole router: one harness attempt = one pass
  over all candidates.
- Request `Model` is ignored: each candidate's own `Model` is used.
- Blobs from one provider are dropped by the other provider's adapter
  (adapters already do this), so switching candidates mid-run is safe.

### CountTokens and Capabilities

- `CountTokens`: delegate to candidate 0 with `Model` replaced; return its result and error unchanged.
- `Capabilities`: `ToolCalling` = all candidates true; `PromptCaching` and
  `Streaming` = candidate 0's value; `MaxContextTokens` = the smallest
  non-zero value over all candidates (0 if all are 0).

### Harness change

Where the harness writes `model_call_completed`:
1. Set `provider = resp.Provider`, `model = resp.Model`.
2. Price: `p := cfg.Price; if mp, ok := cfg.Prices[resp.Model]; ok { p = mp }`, then
   `cost.UsdMicros = p.Cost(resp.Usage)`.

`model_call_started` keeps writing `deps.Model.Provider()` (`"router"`) and
`cfg.Model` (the primary model).

### Agent config change

In the model section of `agent.yaml` (see brief 0.9.1 for the existing keys)
add an optional list:

```yaml
model:
  provider: anthropic
  name: ${ADLC_ANTHROPIC_MODEL}
  pricing: {input_per_mtok: "...", output_per_mtok: "..."}   # existing, from 0.9.1
  fallbacks:
    - provider: openai
      name: ${ADLC_OPENAI_MODEL}
      pricing: {input_per_mtok: "...", output_per_mtok: "..."}
```

Add a field `Fallbacks []Model` with YAML key `fallbacks` to `agentconfig.Model`. A fallback is
decoded into the same `Model` struct; a fallback that itself has `fallbacks`
is a validation problem (`model.fallbacks[i].fallbacks: not allowed`). The
`${VAR}` expansion of task 0.9.1 applies to each fallback's `name` too. Add
`func (a *Agent) Prices() map[string]model.Price` (model name → price, for
the primary and every fallback) and set `harness.Config.Prices` from it.

Each fallback uses the same struct as the primary minus `fallbacks` (no
nesting). Validation: `provider` must be a known provider; `name` non-empty;
a fallback must not repeat the primary's provider+name pair. Error messages
follow the 0.9.1 style (path prefix such as `model.fallbacks[0].name: is required`).

In `adlc run` (`internal/cli/wiring.go`, `buildModel` and `harnessConfig` from task 0.9.2): if `len(fallbacks) > 0`, build each
adapter exactly as the primary is built, wrap them in
`router.New(primary, fallbacks...)`, pass the router as `Deps.Model`, and fill
`Config.Prices` with every candidate's name → price.

## Tests

Router tests use two `model.Fake`s. Build retryable errors as
`&model.Error{Class: adlcv1.ErrorClass_ERROR_CLASS_RATE_LIMIT, HTTPStatus: 429, Retryable: true}`
and non-retryable ones with `HTTPStatus: 400, Retryable: false`.

| Test | Asserts |
|------|---------|
| `TestNewRejectsEmpty` | `New()` returns `ErrNoCandidates` |
| `TestPrimaryAnswers` | primary succeeds: response `Provider == "fake"`, `Model == "m1"`; the fallback fake received 0 requests |
| `TestFallbackOnRetryableError` | primary returns a 429 error: response comes from candidate 1 with `Model == "m2"`; each fake got exactly 1 request; the fallback's request has `Model == "m2"` |
| `TestNoFallbackOnPermanentError` | primary returns a 400 error: `Generate` returns that error (`errors.As` gives HTTP 400); fallback got 0 requests |
| `TestNoFallbackOnRefusal` | primary returns a response with `Finish == FINISH_REASON_REFUSAL`: it is returned; fallback got 0 requests |
| `TestAllCandidatesFail` | both return 429: error message starts with `router: all 2 candidates failed:`; `model.IsRetryable(err)` is true |
| `TestCancelledContextStops` | ctx cancelled before the call: returns `context.Canceled`; no fake got a request |
| `TestRequestNotModified` | after `Generate`, the caller's `req.Model` is unchanged |
| `TestEveryCallStartsAtPrimary` | primary script: [429 error, success]; fallback script: [success]. Call 1 is answered by the fallback, call 2 by the primary |
| `TestCapabilitiesCombine` | `MaxContextTokens` is the smallest non-zero value; `ToolCalling` false if any candidate is false |
| `TestHarnessRecordsServedModel` (harness package) | a run through a router whose primary fails with 429: the `model_call_completed` event has `provider == "fake"` and `model == "m2"`, and its cost uses `Prices["m2"]` |
| `TestFallbacksConfig` (agentconfig package) | valid YAML with one fallback loads; a fallback with empty `name` gives an error containing `model.fallbacks[0].name`; a fallback equal to the primary is rejected |

## Out of scope

- Different models per role or per step type (one candidate list per agent in M1).
- Health tracking, circuit breakers, remembering that a provider is down.
- Fallback on refusal.

## Pitfalls

- Copy the request before setting `Model`; never write to the caller's `*Request`.
- `IsRetryable` must see through `fmt.Errorf("...: %w")` wrapping; use `%w`, not `%v`.
- Do not sleep in the router; the harness handles backoff.
- The proto change must only add fields with new numbers (8 and 9). Never
  renumber existing ones.
- Adding fields to `model.Response` means every adapter must set them; forgetting
  one leaves empty provider/model in the log. The per-adapter assertions catch this.
