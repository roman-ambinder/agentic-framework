# 1.6.1 — Context manager: budgets and compaction

Size: M · Depends on: 0.5.1 · Branch: `task/1.6.1-context-budgets` · PR title: `1.6.1: context manager with token budget and tool output elision`

## Goal

Long runs collect many tool outputs, and the conversation grows until it no
longer fits the model's context window. A new package `internal/contextmgr`
takes the full transcript the harness rebuilds each step and, when the
estimated size is over budget, replaces old tool outputs with a short
placeholder. Nothing is ever removed: every tool call keeps its tool result,
so the conversation stays valid for every provider. If even that is not
enough, the run ends with a clear error instead of an API failure.

The event log is not changed: full outputs stay in the log. Only the request
sent to the model is compacted.

## Design

### Why an estimate, and which one

Asking the provider to count tokens on every step costs a network call per
step. Instead the manager estimates: **tokens ≈ bytes / 4**, rounded up. For
English text and source code that is close enough when the budget keeps a
safety margin (the default budget is 80 % of the context window, see below).
An exact count is optional (`Budget.Count`) and used only near the limit.

### API

```go
package contextmgr

// Budget limits the size of one model request.
type Budget struct {
	// MaxInputTokens is the budget for system + tools + messages.
	// 0 means no limit: Build returns the request unchanged.
	MaxInputTokens int64
	// KeepRecentSteps is how many of the latest assistant messages (and
	// the tool results answering them) are never elided. 0 means 2.
	KeepRecentSteps int
	// Count, if set, gives an exact token count. It is called only when
	// the estimate is within 10% of MaxInputTokens.
	Count func(ctx context.Context, req *model.Request) (int64, error)
}

// Stats describes what Build did.
type Stats struct {
	EstimatedTokens int64 // estimate of the returned request
	ElidedResults   int   // tool results replaced by a placeholder
}

// ErrContextTooLarge means the request does not fit even after eliding
// every tool result outside the protected window.
var ErrContextTooLarge = errors.New("contextmgr: context budget exceeded")

// Build returns a copy of req whose messages fit the budget. req itself is
// never modified.
func Build(ctx context.Context, req *model.Request, b Budget) (*model.Request, Stats, error)

// EstimateTokens returns (len(s)+3)/4.
func EstimateTokens(s string) int64

// EstimateRequest estimates the whole request: System, every tool's
// Name + Description + InputSchema, and every part of every message
// (text; tool call name + arguments; tool result content; blob data).
func EstimateRequest(req *model.Request) int64
```

### Placeholder text (exact)

```go
fmt.Sprintf("[tool output elided: %d bytes; call the tool again if you need it]", n)
```

`n` is `len(original Content)`. A result whose Content already starts with
`[tool output elided:` is never elided again.

### Build algorithm

```
1. if b.MaxInputTokens == 0: return deepCopy(req), Stats{EstimatedTokens: EstimateRequest(req)}, nil
2. keep := b.KeepRecentSteps; if keep == 0 { keep = 2 }
3. out := deepCopy(req)          // copy Messages and Parts slices and the ToolResult structs you change
4. est := EstimateRequest(out)
5. if fits(ctx, out, est, b) (step 9): return out, Stats{est, 0}, nil
6. protectedFrom := index of the keep-th assistant message counted from the end
                    (0 if there are fewer than keep assistant messages)
   protected messages: index 0 (the task) and every index >= protectedFrom
7. for i := 1; i < protectedFrom; i++:           // oldest first
       if out.Messages[i].Role != RoleUser: continue
       for j, p := range out.Messages[i].Parts:
           if p.Kind != PartToolResult or already elided: continue
           old := EstimateTokens(p.ToolResult.Content)
           replace Content with the placeholder
           est = est - old + EstimateTokens(placeholder)
           elided++
           if est <= b.MaxInputTokens: goto 8
8. if fits(ctx, out, est, b): return out, Stats{est, elided}, nil
   return out, Stats{est, elided}, fmt.Errorf("%w: needs about %d tokens, budget is %d",
                                              ErrContextTooLarge, est, b.MaxInputTokens)
9. fits(ctx, r, est, b):
       if est > b.MaxInputTokens: return false
       if b.Count == nil or est < b.MaxInputTokens*9/10: return true
       n, err := b.Count(ctx, r)
       if err != nil: return true          // estimate fits; do not fail the run on a count error
       return n <= b.MaxInputTokens
```

If `Count` says the request does not fit after step 7 has elided everything
it can, return `ErrContextTooLarge` with `n` instead of `est` in the message.
If it says "does not fit" at step 5, continue with step 6 as if the estimate
were over.

Invariants (tests check them):
- The number of messages and the number and order of parts never change.
- `CallID` and `IsError` of every tool result never change.
- Message 0 and the protected window are byte-identical to the input.
- Elision always picks the oldest eligible result first.

### Harness change

1. `harness.Config` gets a field (add this to `interfaces.md` §6):

   ```go
   	// Context limits the size of each model request (task 1.6.1).
   	// MaxInputTokens 0 = derived from the adapter's MaxContextTokens.
   	Context contextmgr.Budget
   ```

2. At the start of `Run`, compute the effective budget once:
   `b := cfg.Context`; if `b.MaxInputTokens == 0` and
   `deps.Model.Capabilities().MaxContextTokens > 0`, set
   `b.MaxInputTokens = int64(caps.MaxContextTokens) * 8 / 10`.
   If `b.Count == nil`, leave it nil (exact counting is opt-in).
3. In `buildRequest` (after the transcript is set as `Messages`):
   `r, _, err := contextmgr.Build(ctx, req, b)`.
   - On `errors.Is(err, contextmgr.ErrContextTooLarge)`: end the run with
     stop reason `STOP_REASON_ERROR`, detail `"context budget exceeded"`
     (write `error_occurred` with class `ERROR_CLASS_INTERNAL` and the error
     text first, then `run_completed`).
   - Otherwise send `r` instead of `req`.

### Agent config (optional section)

```yaml
context:

```

Map to `harness.Config.Context`. Validation: both must be ≥ 0. Follow the
existing loader style in `internal/agentconfig`.

## Out of scope

- Summarizing old turns with a model.
- Removing messages or turns.
- Server-side compaction or context-editing features of any provider.
- Keeping cache prefixes stable across steps (task 1.6.2).
- Recording elisions in the event log.

## Pitfalls

- Deep-copy before changing anything: `Parts` slices and `*ToolResult`
  pointers are shared with the transcript; changing them in place corrupts the
  next step's input.
- Never elide tool *calls* or assistant text; only tool result content.
- Never remove a message: providers reject a tool call without its result.
- The protected window counts assistant messages, not all messages.
- `int64` everywhere for token counts; do not mix `int` and `int64` in comparisons.
