# 1.1 — Anthropic adapter: streaming, prompt caching, token counting

Size: M · Depends on: 0.5b · Branch: `task/1.1-anthropic-full` · PR title: `1.1: anthropic adapter streaming, caching and token counting`

## Goal

The Anthropic adapter in `internal/model/anthropic` (created in task 0.5b with
non-streaming `Messages.New`) is extended so that:

1. `Generate` always uses the streaming API internally and returns one
   complete `*model.Response`, so long outputs never hit HTTP timeouts.
2. Prompt caching is on by default: the system prompt carries a cache
   breakpoint and the request has top-level automatic caching, and cache
   token counts reach `model.Usage`.
3. `CountTokens` calls the token counting endpoint.
4. `Capabilities` reports `Streaming: true` and `PromptCaching: true`.

The `model.Adapter` interface does not change. Callers see no difference
except fewer timeouts, cache tokens in usage, and real token counts.

## Design

### Symbols used (all verified against anthropic-sdk-go/v2 v2.9.0)

```go
import (
	"github.com/anthropics/anthropic-sdk-go/v2"
	"github.com/anthropics/anthropic-sdk-go/v2/option"

client.Messages.NewStreaming(ctx, params) *ssestream.Stream[anthropic.MessageStreamEventUnion]

func (acc *anthropic.Message) Accumulate(event anthropic.MessageStreamEventUnion) error

// TextBlockParam.CacheControl    CacheControlEphemeralParam
// MessageCountTokensParams fields: Model, Messages, System (MessageCountTokensParamsSystemUnion
//   with OfTextBlockArray []TextBlockParam), Tools ([]MessageCountTokensToolUnionParam with OfTool *ToolParam),
//   OutputConfig, Thinking
// Usage fields: InputTokens, OutputTokens, CacheReadInputTokens, CacheCreationInputTokens (all int64)
```

### Generate (streaming)

```
func (a *Adapter) Generate(ctx, req) (*model.Response, error):
 1. params, err := a.buildParams(req)            // unchanged from 0.5b
    if err != nil: return nil, err
 2. if !a.opts.DisableCaching: applyCaching(&params)
 3. stream := a.client.Messages.NewStreaming(ctx, params)
    defer stream.Close()
 4. msg := anthropic.Message{}
    for stream.Next():
        if err := msg.Accumulate(stream.Current()); err != nil:
            return nil, &model.Error{Class: ERROR_CLASS_MODEL, Retryable: false,
                                     Err: fmt.Errorf("anthropic: accumulate stream: %w", err)}
 5. if err := stream.Err(); err != nil:
        return nil, classify(ctx, err)            // same classifier as 0.5b uses for Messages.New
 6. if msg.StopReason == "":                     // stream ended without message_delta
        return nil, &model.Error{Class: ERROR_CLASS_MODEL, Retryable: true,
                                 Err: errors.New("anthropic: stream ended before the message was complete")}
 7. return toResponse(&msg), nil               // unchanged from 0.5b
```

Keep the 0.5b non-streaming code path only if 0.5b's tests need it; otherwise
delete it so there is one code path. All 0.5b tests must still pass: change
their test servers to answer with SSE (see "Test server" below) where needed.

### applyCaching

```
func applyCaching(p *anthropic.MessageNewParams):
 1. if len(p.System) > 0:
        p.System[len(p.System)-1].CacheControl = anthropic.NewCacheControlEphemeralParam()
 2. p.CacheControl = anthropic.NewCacheControlEphemeralParam()
```

Why these two: requests render in the order tools → system → messages. A
breakpoint on the last system block caches tools + system. The top-level
`CacheControl` lets the API place a breakpoint on the last cacheable block of
the messages, so the conversation history is cached too. That is 2 of the
allowed 4 breakpoints.

### Usage mapping (in `toResponse`, check that 0.5b already does this; add it if not)

| `model.Usage` | from `msg.Usage` |
|---------------|------------------|
| `InputTokens` | `InputTokens` |
| `OutputTokens` | `OutputTokens` |
| `CacheReadTokens` | `CacheReadInputTokens` |
| `CacheWriteTokens` | `CacheCreationInputTokens` |

The API's `input_tokens` already excludes cached tokens, so do not subtract.

`Accumulate` keeps usage fields from `message_start` unless `message_delta`
sends them again (checked in SDK source `messageutil.go`), so cache counts
from `message_start` survive.

### CountTokens

```
func (a *Adapter) CountTokens(ctx, req) (int64, error):
 1. params, err := a.buildParams(req)
 2. cp := anthropic.MessageCountTokensParams{
        Model:    params.Model,
        Messages: params.Messages,
        OutputConfig: params.OutputConfig,
        Thinking: params.Thinking,
    }
    if len(params.System) > 0:
        cp.System = anthropic.MessageCountTokensParamsSystemUnion{OfTextBlockArray: params.System}
    for each t in params.Tools:
        if t.OfTool != nil: cp.Tools = append(cp.Tools, anthropic.MessageCountTokensToolUnionParam{OfTool: t.OfTool})
 3. res, err := a.client.Messages.CountTokens(ctx, cp)
    if err != nil: return 0, classify(ctx, err)
 4. return res.InputTokens, nil
```

## Out of scope

- Server-side refusal fallbacks and the beta `fallbacks` parameter.
- Exposing stream deltas to callers (no streaming in `model.Adapter`).

- Reading context window sizes from the Models API.

## Pitfalls

- Always `defer stream.Close()`, also on the error paths.
- Do not stop at the first `message_stop`-less end: check `stream.Err()` first,
  then `msg.StopReason == ""`.
- The SDK retries on its own by default. 0.5b set `option.WithMaxRetries(0)`
  so the harness owns retries; keep it, also for `CountTokens`.
- Prompts shorter than the model's minimum cacheable length (a few thousand
  tokens, model-dependent) silently do not cache. That is why the live test
  uses a long system prompt; unit tests only check the request body.
- Never put a timestamp or anything per-request into the system prompt: any
  byte change before a breakpoint invalidates the cache.
- Tool `input` arrives as JSON built from `partial_json` chunks; compare JSON
  by value in tests, never by string.
- Do not hard-code a model id anywhere. Tests use `"test-model"`; the live
  test reads `ADLC_ANTHROPIC_MODEL`.
