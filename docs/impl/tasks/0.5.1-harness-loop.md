# 0.5.1 — Harness core loop

Size: M · Depends on: 0.4, 0.6, 0.7.1 · Branch: `task/0.5.1-harness-loop` · PR title: `0.5.1: harness core loop and transcript`

## Goal

Package `internal/harness` runs an agent: it calls the model, runs the tool
calls the model asks for (after a policy check), feeds results back, and
stops with one of the stop reasons in `interfaces.md §6.2`. Every step is
written to the event log in the order of `interfaces.md §6.1`, and the
conversation for each model call is rebuilt from the log by `Transcript`.

Budgets (0.5.2), retries (0.5.3), hooks and checkpoints (0.5.4) are **not**
part of this task; the code must leave obvious places for them (named below).

## Design

### Signatures

As `interfaces.md §6`, with one change (proposed for `interfaces.md §6`):

```go
// Transcript rebuilds the conversation from a run's events. Tool outputs are
// capped with toolrouter.ForModel(output, maxToolOutputBytes) exactly as the
// model saw them; maxToolOutputBytes <= 0 means toolrouter.DefaultMaxModelBytes.
func Transcript(events []*adlcv1.Event, maxToolOutputBytes int) ([]model.Message, error)
```

In this task `Config.Retry` and `Config.Hooks` are declared (types from
0.5.3 / 0.5.4 are added then); for now declare only the fields this task
uses and leave `Retry`/`Hooks` out — 0.5.3 and 0.5.4 add them.

### Defaults and validation (harness.go)

`Run` first applies defaults: `Deps.Now = time.Now`, `Deps.Sleep = sleepCtx`
(a timer that returns `ctx.Err()` if ctx ends first), `Config.MaxTokens = 4096`,
`Config.MaxToolOutputBytes = toolrouter.DefaultMaxModelBytes` — each only when zero/nil.

Then it validates; on failure it returns `nil, err` **without writing any event**:

| Check | Error text |
|-------|-----------|
| `cfg.RunID == ""` | `harness: config: run id is empty` |
| `cfg.Task == ""` | `harness: config: task is empty` |
| `deps.Log == nil` | `harness: deps: log is nil` |
| `deps.Model == nil` | `harness: deps: model is nil` |
| `deps.Tools == nil` | `harness: deps: tools is nil` |
| `deps.Policy == nil` | `harness: deps: policy is nil` |

### recorder (recorder.go)

```go
type recorder struct {
	ctx     context.Context // context.WithoutCancel(parent): log writes survive cancellation
	log     Log
	runID   string
	agentID string
	events  []*adlcv1.Event   // every event appended, as stored
	state   eventlog.RunState // events applied in order
}

// add sets RunId and AgentId on ev, appends it to the log, applies the
// stored event to r.state and returns its seq. Any error is returned as is.
func (r *recorder) add(ev *adlcv1.Event) (uint64, error)
```

`add` must call `r.state.Apply(stored)`; if that fails the harness wrote an
invalid sequence — return the error (it is a bug, the tests must catch it).
Time is filled in by the store (do not set `ev.Time`).

Callers build events like:
```go
seq, err := r.add(&adlcv1.Event{ParentSeq: startSeq, Payload: &adlcv1.Event_ModelCallCompleted{ModelCallCompleted: &adlcv1.ModelCallCompleted{...}}})
```

### The loop (loop.go)

```
Run(ctx, cfg, deps):
 1. defaults + validation (above)
 2. r := newRecorder(ctx, deps.Log, cfg.RunID, cfg.AgentID)
 3. add run_started{agent_version: cfg.AgentVersion, task: cfg.Task, budget: cfg.Budget}
 4. tools := deps.Tools.Tools(); byName := map name → Tool; specs := []ToolSpec in Tools() order
 5. for step := 1; ; step++:
      a. if ctx.Err() != nil → return finish(CANCELLED, "", "")
         [0.5.2 adds the budget check here]
      b. msgs, err := Transcript(r.events, cfg.MaxToolOutputBytes)   (err → return nil, err: bug)
      c. req := &model.Request{Model, System, Messages: msgs, Tools: specs, MaxTokens, Effort}
      d. callID := fmt.Sprintf("m%d", step)
      e. startSeq := add model_call_started{call_id, step, provider: deps.Model.Provider(), model: cfg.Model, attempt: 1}
         [0.5.3 turns e–g into a retry loop]
      f. t0 := deps.Now(); resp, err := deps.Model.Generate(ctx, req)
      g. if err != nil:
           if ctx.Err() != nil → return finish(CANCELLED, "", "")
           add model_call_failed{call_id, error_class, message: err.Error(), will_retry: false, http_status}
             (error_class and http_status from *model.Error via errors.As; otherwise ERROR_CLASS_INTERNAL, 0)
           return finish(ERROR, "", err.Error())
      h. add model_call_completed (parent_seq = startSeq), see "Recording a response" below
      i. if resp.Finish == REFUSAL → return finish(ERROR, "", "model refused")
      j. calls := resp.Message.ToolCalls()
         if len(calls) == 0:
           if resp.Finish == MAX_TOKENS → return finish(ERROR, "", "output limit reached")
           return finish(COMPLETED, resp.Message.Text(), "")
      k. for i, call := range calls:
           if call.ID == "" { call.ID = fmt.Sprintf("%s-t%d", callID, i+1) }
           stop := runToolCall(call)          (below); if stop != nil → return it
         [0.5.4 adds the checkpoint here]
```

`finish(reason, result, detail)` adds `run_completed{stop_reason, result, detail}`
and returns `&r.state, nil` (a copy of the state is fine). For DENIED and
AWAITING_APPROVAL the events written before finish are described below.

Any error returned by `r.add` is returned from `Run` immediately as
`nil, fmt.Errorf("harness: %w", err)`.

### runToolCall

```
 1. if ctx.Err() != nil → finish(CANCELLED)
 2. tool, known := byName[call.Name]
 3. reqSeq := add tool_call_requested{
        call: {id: call.ID, name: call.Name, arguments_json: string(call.Arguments)},
        risk_class: tool.Risk (UNSPECIFIED if !known), server: tool.Server ("" if !known)}
 4. if !known:
        add tool_call_completed{call_id, is_error: true,
            output: `unknown tool "<name>"; available tools: <names sorted, joined with ", ">`}
            (parent_seq = reqSeq)
        return nil      ← the model sees the error and can correct itself; the run continues
    [0.5.4 runs PreTool hooks here]
 5. dec, err := deps.Policy.Authorize(ctx, policy.Request{AgentID, Tool: call.Name, Risk: tool.Risk, ArgumentsJSON})
    if err != nil:
        if ctx.Err() != nil → finish(CANCELLED)
        add error_occurred{error_class: POLICY, message: err.Error(), component: "policy"}
        → finish(ERROR, "", "policy: " + err.Error())
 6. add policy_decided{call_id, decision, rule_id, reason, source} (parent_seq = reqSeq)
 7. switch dec.Decision:
      DENY → finish(DENIED, "", fmt.Sprintf("rule %s: %s", dec.RuleID, dec.Reason))
      NEEDS_APPROVAL →
        add approval_requested{approval_id: "a-" + call.ID, call_id,
                               summary: call.Name + " " + string(call.Arguments)}
        → finish(AWAITING_APPROVAL, "", "")
      ALLOW → continue
      anything else → finish(ERROR, "", "policy returned no decision")
 8. t0 := deps.Now(); res, err := deps.Tools.Call(ctx, call); dur := deps.Now().Sub(t0)
 9. if err != nil:
        if ctx.Err() != nil → finish(CANCELLED)
        add error_occurred{error_class: TOOL, message: err.Error(), component: "toolrouter"}
        res = toolrouter.Result{Output: []byte("tool call failed: " + err.Error()), IsError: true}
 10. _, truncated := toolrouter.ForModel(res.Output, cfg.MaxToolOutputBytes)
 11. add tool_call_completed{call_id, is_error: res.IsError, output: res.Output,
         truncated_for_model: truncated, duration: durationpb.New(dur), exit_code: res.ExitCode}
         (parent_seq = reqSeq)
    [0.5.4 runs PostTool hooks here]
 12. return nil
```

Tool calls run one after another, in the order the model returned them.
When one call stops the run, later calls in the same response are not requested.

### Recording a response

```
model_call_completed{
  call_id, finish_reason: resp.Finish, provider_finish_reason: resp.ProviderFinish,
  text: resp.Message.Text(),
  tool_calls: one adlcv1.ToolCall per resp.Message.ToolCalls() (with IDs as assigned in step k),
  provider_blobs: for each part p at index i in resp.Message.Parts with p.Kind == PartBlob:
                  {provider: p.Blob.Provider, kind: p.Blob.Kind, data: p.Blob.Data, index: uint32(i)},
  latency: durationpb.New(deps.Now().Sub(t0)),
}
cost = {input_tokens, output_tokens, cache_read_tokens, cache_write_tokens from resp.Usage,
        usd_micros: cfg.Price.Cost(resp.Usage)}
```

Assign missing tool-call IDs (step k) **before** recording the response, so
the IDs in `model_call_completed.tool_calls` and in `tool_call_requested` match.

### Transcript (transcript.go)

Walk the events in order:

| Event | Effect |
|-------|--------|
| first event | must be `run_started`, else error `harness: transcript: first event is <kind>, want run_started` |
| `run_started` | append `Message{RoleUser, [TextPart(task)]}` |
| `model_call_completed` | flush pending tool results (below); build the assistant message: parts = `[TextPart(text)]` if text non-empty, then one `ToolCallPart` per tool call (`Arguments: json.RawMessage(arguments_json)`, `"{}"` if empty); then insert each blob, in ascending `index` order, at position `min(index, len(parts))` as `BlobPart`; append the message |
| `tool_call_completed` | add `ToolResultPart{CallID, Content: text from toolrouter.ForModel(output, max), IsError}` to the pending tool results |
| anything else | ignored |

"Flush pending tool results": if there are any, append one
`Message{RoleUser, parts}` with all pending results in event order, then clear.
Flush once more after the last event.

## Out of scope

- Budgets (0.5.2), retries (0.5.3), hooks and checkpoints (0.5.4).
- Running tool calls in parallel.
- Resuming a paused or crashed run (1.7); approvals beyond writing `approval_requested`.
- Context-window management (1.6.x): `Transcript` sends the whole history.

## Pitfalls

- The generated oneof interface (`isEvent_Payload`) is unexported; you cannot
  write a helper that takes "a payload". Pass whole `*adlcv1.Event` values to `recorder.add`.
- Write events with `context.WithoutCancel(ctx)` (the recorder's ctx), but call
  the model, policy and tools with the **original** `ctx` so cancellation stops them.
- `eventlog.Fold` rejects a `tool_call_completed` without a matching
  `tool_call_requested`, and duplicate pending IDs. If `recorder.add` fails
  with `invalid log`, the harness wrote events in the wrong order.
- Until task 0.5.2 lands there is no step limit: a scripted fake that always
  calls a tool loops until the script is exhausted. Never run this against a real model before 0.5.2.
- `resp.Message.ToolCalls()` returns copies; assign missing IDs on the slice you then use everywhere.
- Do not set `Event.Time` or `Event.Seq`; the store does.
