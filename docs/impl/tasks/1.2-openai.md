# 1.2 — OpenAI adapter

Size: M · Depends on: 0.4, 0.9.2 · Branch: `task/1.2-openai` · PR title: `1.2: openai chat completions adapter`

## Goal

A `model.Adapter` for the OpenAI Chat Completions API in
`internal/model/openai`, built on `github.com/openai/openai-go/v3` v3.99.0.
It maps `model.Request` to a chat completion request and the answer back to
`model.Response`, classifies errors as `interfaces.md §2.1` says, and has a
configurable base URL so OpenAI-compatible servers (for example local model
servers) work too. Non-streaming only.

## Design

Package name `openai`. Import the SDK with an alias to avoid the clash:

```go
import (
	oai "github.com/openai/openai-go/v3"
	"github.com/openai/openai-go/v3/option"
	"github.com/openai/openai-go/v3/shared"
)
```

### Public API

```go
// Config configures the adapter.
type Config struct {
	APIKey           string        // "" = the SDK reads OPENAI_API_KEY
	BaseURL          string        // "" = SDK default; set for compatible servers
	HTTPClient       *http.Client  // nil = SDK default; tests pass the test server's client
	MaxContextTokens int           // reported by Capabilities; 0 = unknown
	RequestTimeout   time.Duration // 0 = none (ctx still applies)
}

// Adapter implements model.Adapter for OpenAI Chat Completions.
type Adapter struct {
	cfg    Config
	client oai.Client
}

// New builds an adapter. It never fails today but returns an error so
// validation can be added without changing callers.
func New(cfg Config) (*Adapter, error)

func (a *Adapter) Provider() string // "openai"
func (a *Adapter) Generate(ctx context.Context, req *model.Request) (*model.Response, error)
func (a *Adapter) CountTokens(ctx context.Context, req *model.Request) (int64, error)
func (a *Adapter) Capabilities() model.Caps
```

`New` builds `oai.NewClient(opts...)` with, in this order:
`option.WithMaxRetries(0)` (the harness owns retries; always set),
`option.WithAPIKey(cfg.APIKey)` if non-empty,
`option.WithBaseURL(cfg.BaseURL)` if non-empty,
`option.WithHTTPClient(cfg.HTTPClient)` if non-nil,
`option.WithRequestTimeout(cfg.RequestTimeout)` if non-zero.

### Request mapping (`buildParams(req *model.Request) (oai.ChatCompletionNewParams, error)`)

1. `p := oai.ChatCompletionNewParams{Model: shared.ChatModel(req.Model)}`
2. If `req.System != ""`: append `oai.SystemMessage(req.System)` to `p.Messages`.
3. For each `m` in `req.Messages`, in order:
   - `RoleUser`:
     1. For each part with `Kind == PartToolResult`, in part order: append
        `oai.ToolMessage(part.ToolResult.Content, part.ToolResult.CallID)`.
        If `IsError`, prefix the content with `"error: "` (the API has no
        error flag for tool messages).
     2. Join all `PartText` texts with `"\n"`; if the result is non-empty,
        append `oai.UserMessage(text)`.
     3. Tool results go first because the API requires tool messages to come
        right after the assistant message that asked for them.
   - `RoleAssistant`:
     1. `text := m.Text()`; `calls := m.ToolCalls()`.
     2. If both are empty, skip the message.
     3. Build `a := oai.ChatCompletionAssistantMessageParam{}`;
        if `text != ""`: `a.Content.OfString = oai.String(text)`.
     4. For each call: append to `a.ToolCalls`:
        `oai.ChatCompletionMessageToolCallUnionParam{OfFunction: &oai.ChatCompletionMessageFunctionToolCallParam{ID: c.ID, Function: oai.ChatCompletionMessageFunctionToolCallFunctionParam{Name: c.Name, Arguments: string(c.Arguments)}}}`.
     5. Append `oai.ChatCompletionMessageParamUnion{OfAssistant: &a}`.
     6. `PartBlob` parts are ignored (this adapter owns no blobs; blobs of
        other providers must never be sent).
4. Tools: for each `t` in `req.Tools`:
   1. Unmarshal `t.InputSchema` into `map[string]any`. On error return
      `fmt.Errorf("openai: tool %q: input schema is not a JSON object: %w", t.Name, err)`.
   2. Append `oai.ChatCompletionFunctionTool(shared.FunctionDefinitionParam{Name: t.Name, Description: oai.String(t.Description), Parameters: shared.FunctionParameters(schema)})`.
5. If `len(req.Tools) > 0`: `p.ToolChoice.OfAuto = oai.String("auto")`.
   Never set a forced tool choice.
6. If `req.MaxTokens > 0`: `p.MaxCompletionTokens = oai.Int(int64(req.MaxTokens))`.
7. If `req.Effort != ""`: `p.ReasoningEffort = shared.ReasoningEffort(req.Effort)`.
   (Valid SDK values include `low`, `medium`, `high`, `xhigh`, `max`; models
   without reasoning reject this field, so agents for those models leave
   `effort` empty in config.)

### Response mapping (`toResponse(c *oai.ChatCompletion) (*model.Response, error)`)

1. If `len(c.Choices) == 0`: return
   `&model.Error{Class: ERROR_CLASS_MODEL, Retryable: true, Err: errors.New("openai: response has no choices")}`.
2. `ch := c.Choices[0]`; `msg := ch.Message`.
3. Parts: if `msg.Content != ""`, a text part. For each `tc` in `msg.ToolCalls`
   with `tc.Type == "function"`: `f := tc.AsFunction()`, then a tool-call part
   `model.ToolCall{ID: f.ID, Name: f.Function.Name, Arguments: args(f.Function.Arguments)}`.
   Ignore other tool call types.
4. `args(s string) json.RawMessage`: `""` → `{}`; `json.Valid([]byte(s))` →
   `json.RawMessage(s)`; otherwise `json.RawMessage(strconv.Quote(s))` (a JSON
   string, so the tool rejects it and the model sees an error it can correct).
5. Finish reason:

   | `ch.FinishReason` | `model.Response.Finish` |
   |-------------------|-------------------------|
   | `"stop"` | `FINISH_REASON_END_TURN` |
   | `"tool_calls"` | `FINISH_REASON_TOOL_USE` |
   | `"length"` | `FINISH_REASON_MAX_TOKENS` |
   | `"content_filter"` | `FINISH_REASON_REFUSAL` |
   | anything else | `FINISH_REASON_OTHER` |

   After the table: if `msg.Refusal != ""`, set `Finish = FINISH_REASON_REFUSAL`
   and use the refusal text as the text part. `ProviderFinish = ch.FinishReason`.
6. Usage (`c.Usage`, type `oai.CompletionUsage`). OpenAI counts cached tokens
   inside `prompt_tokens`; the framework counts them separately (same as the
   Anthropic adapter), so subtract:

   | `model.Usage` | value |
   |---------------|-------|
   | `InputTokens` | `PromptTokens - PromptTokensDetails.CachedTokens` (never below 0) |
   | `CacheReadTokens` | `PromptTokensDetails.CachedTokens` |
   | `CacheWriteTokens` | `PromptTokensDetails.CacheWriteTokens` |
   | `OutputTokens` | `CompletionTokens` |

### Errors (`classify(ctx context.Context, err error) error`)

1. If `ctx.Err() != nil`: return `ctx.Err()` unchanged (not retryable).
2. `var apiErr *oai.Error`; if `errors.As(err, &apiErr)`: use `apiErr.StatusCode`
   with the table in `interfaces.md §2.1` and return
   `&model.Error{Class: ..., HTTPStatus: apiErr.StatusCode, Retryable: ..., Err: err}`.
3. Otherwise (network error, timeout): `&model.Error{Class: ERROR_CLASS_TIMEOUT, Retryable: true, Err: err}`.

### CountTokens

There is no token counting endpoint for Chat Completions. Estimate:
`buildParams`, `json.Marshal` the params, return `int64((len(b) + 3) / 4)`.
Document in the doc comment that it is an estimate (about 4 bytes per token).

### Capabilities

`model.Caps{ToolCalling: true, PromptCaching: true, Streaming: false, MaxContextTokens: cfg.MaxContextTokens}`.
(Prompt caching is automatic on the OpenAI side; there is nothing to set.)

### Fixtures (`testdata/`)

`tool_call.json`:
```json
{"id":"chatcmpl-1","object":"chat.completion","created":1,"model":"test-model",
 "choices":[{"index":0,"finish_reason":"tool_calls","message":{"role":"assistant","content":"Reading the file.","refusal":null,
   "tool_calls":[{"id":"call_1","type":"function","function":{"name":"fs__read_file","arguments":"{\"path\":\"main.go\"}"}}]}}],
 "usage":{"prompt_tokens":120,"completion_tokens":25,"total_tokens":145,"prompt_tokens_details":{"cached_tokens":100}}}
```

`end_turn.json`: same shape, `finish_reason` `"stop"`, `content` `"Done."`, no `tool_calls`,
usage `{"prompt_tokens":50,"completion_tokens":3,"total_tokens":53}`.

`refusal.json`: `finish_reason` `"stop"`, `content` `null`, `refusal` `"I can't help with that."`.

`bad_arguments.json`: like `tool_call.json` but `"arguments":"{\"path\":"` (truncated JSON).

Test server: `httptest.NewServer` that records the request body and answers
`POST /chat/completions` with status 200, `Content-Type: application/json` and
the fixture. Pass `BaseURL: srv.URL` and `HTTPClient: srv.Client()`. For error
tests answer with the status code and body
`{"error":{"message":"x","type":"server_error","code":null}}`.

## Pitfalls

- Learned in task 1.1 (Anthropic): an error that arrives in the middle of a streamed response can carry HTTP status 200, so `model.ClassifyHTTP` alone classifies it as INTERNAL, not retryable. If you stream, test what the OpenAI SDK returns for a mid-stream error and classify it by its error type, as `internal/model/anthropic/errors.go` (`classifyStreamError`) does.
- The package is also named `openai`: always import the SDK as `oai`.
- `option.WithMaxRetries(0)` is required; the SDK otherwise retries 429/5xx itself
  and the harness's retry accounting is wrong. `TestNoRetriesInSDK` guards this.
- Tool messages must directly follow the assistant message with the matching
  `tool_calls`; never put a user text between them.
- Every assistant tool call must get a tool message answer in the next user
  turn, or the API returns 400. The harness guarantees this; do not "fix" it here.
- `prompt_tokens` includes cached tokens; subtract them (see Usage).
- Compare JSON by value in tests (`map[string]any`), not as strings.
- Do not hard-code model ids; tests use `"test-model"`.
