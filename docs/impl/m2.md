# M2 — task list and shared decisions

Gate G1 (work plan §5) decides whether M2 is **M2-C** (control plane) or
**M2-Q** (agent quality). Both are briefed now so that either can start as
soon as G1 is recorded. Each task has a brief in `tasks/`; this file holds
the decisions the briefs share. If a brief disagrees with this file, this
file wins and the brief is fixed.

## Shared decisions

1. **Approvals live in the event log, not a new store.** A paused run already
   has `approval_requested` followed by `run_completed{AWAITING_APPROVAL}`;
   `RunState.PendingApprovals` lists them. Approving or rejecting appends
   `approval_resolved` to the same run and continues it in place (the fold
   already allows exactly that event after a pause).
2. **One control database for everything that is not run history:**
   `.adlc/control.db` (flag `--control-db`, constant `defaultControlDBPath`
   in `internal/cli`), package `internal/controlplane`, SQLite with its own
   `PRAGMA user_version` migrations (same pattern as `internal/eventlog`).
   It holds kill switches and the agent registry. It never holds run events.
3. **The harness learns about the control plane only through small
   interfaces in `harness.Deps`** (like `Log`, `Policy`): a nil dependency
   means "feature off", so every existing caller keeps working unchanged.
4. **Every new command is offline and local**: no server process in M2.
   `adlc serve` (an API in front of the control plane) is an M4 option.
5. **No schema changes to `events.proto` unless a brief says so**, and then
   only additions (AGENTS.md rules 4–5; record them in `interfaces.md` §10).
6. **M2-Q work is measured, never assumed**: every M2-Q feature is
   switchable per agent file, off by default, so `adlc eval` can compare
   with and without it on the same suite.
